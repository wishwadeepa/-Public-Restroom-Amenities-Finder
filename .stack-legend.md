# Technical Stack Legend

## 1. Core Architecture
- **Language & Runtime:** TypeScript (Strict Mode), Node.js LTS (>=18.x)
- **Application Framework:** Next.js 14+ (App Router)
- **UI Framework & Styling:** Tailwind CSS, Radix UI primitives, Lucide React icons
- **State Management & Data Fetching:** TanStack Query (React Query) / React Server Components

## 2. Geospatial & Mapping
- **Mapping Engine:** Leaflet & React-Leaflet
- **Tile Provider:** OpenStreetMap (TileLayer)
- **Clustering:** Leaflet.markercluster
- **Geocoding & Location:** Browser Geolocation API / Nominatim OpenStreetMap API (bounded)

## 3. Data & Storage
- **ORM:** Prisma ORM
- **Database Engine:** PostgreSQL with PostGIS capabilities (SQLite compatible for isolated local test runner)
- **Data Models:**
  - `Amenity` (id, name, type, latitude, longitude, address, isAccessible, feeRequired, hours, createdAt, updatedAt)
  - `AmenityVerification` (id, amenityId, status, verifiedAt, notes)
  - `AmenityReview` (id, amenityId, rating, cleanlinessRating, comment, createdAt)

## 4. Security & Input Validation
- **Schema Validation:** Zod (runtime validation on all API requests and mutation inputs)
- **Sanitization:** DOMPurify / isomorphic-dompurify for user notes and reviews
- **Rate Limiting:** Sliding-window rate limiter middleware on submission and review endpoints
- **Security Headers:** Strict CSP, HSTS, X-Frame-Options, X-Content-Type-Options

## 5. Testing & Quality Assurance
- **Unit & Integration Tests:** Vitest, React Testing Library
- **End-to-End (E2E) Tests:** Playwright
- **Linting & Formatting:** ESLint, Prettier

## 6. Pre-Commit Defenses & Supply Chain
- **Git Hooks:** Husky, lint-staged
- **Secret Scanning:** Gitleaks pre-commit hook
- **Environment Management:** Strict `.env.example` template, zero hardcoded secrets

## 7. Infrastructure & Containerization
- **Containerization:** Multi-stage Dockerfile (Alpine-based, non-root user execution)
- **CI/CD:** GitHub Actions (lint, test, build, security scan)
- **Observability:** Sentry SDK error tracking, `/api/health` readiness/liveness probe
